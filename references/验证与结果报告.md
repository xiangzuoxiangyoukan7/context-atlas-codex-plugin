# 验证与结果报告

## Run the bundled validator

From the project root, run:

```text
py <knowledge-base>/.project-kb/scripts/check_knowledge_base.py <knowledge-base> --schema-root <knowledge-base>/.project-kb/schemas
```

Use `--format json` when another Agent or tool will consume the result. Exit `0` means structurally valid, `1` means validation issues, and `2` means invocation or Schema configuration failure.

Validation covers controlled metadata, lifecycle rules, source and cross-type references, optional current-change records, acceptance/evidence reconciliation, links, technology records, and probable sensitive values. It never decides whether an external task may execute and does not approve business or technical correctness.

## Final report contract

Return these fields after initialization or update:

| Field | Content |
| --- | --- |
| Operation | `initialized`, `updated`, `inspected`, or `validated` |
| Project root | Resolved absolute path |
| Knowledge base | Resolved target path |
| Technology stacks | Confirmed names and unresolved gaps |
| Written files | Created/changed paths; `none` for read-only work |
| Confirmation state | `confirmed`, `awaiting_confirmation`, or `not_applicable`; include revision, confirmer, and time when confirmed |
| Validation result | `passed`, `failed`, or `not_validated`; include command, exit code, issue count, and report location when run |
| Unknowns/conflicts | Remaining IDs and required owner action |
| Next action | One concrete step or `none` |

If validation fails, state failure and leave the target unclaimed. Never report success from a partial command, stale output, or an unavailable second Agent.
