# 初始化协议

## Preconditions

1. Resolve the current or user-selected project root to an absolute path.
2. Confirm it is the intended repository or project directory.
3. Derive the default project name from the final directory segment and the target `doc-<项目目录名>/`.
4. Reject an override containing separators, `.`/`..`, or a target that resolves outside the project root.
5. If the target exists, make no initialization writes. Read its README and `knowledge-base.yaml`, then enter the update workflow.

## Inspect and propose

Inspect repository manifests, build files, source layout, tests, CI, configuration examples, and existing documentation. Do not run mutating project commands. Identify every technology in use and propose its directory, purpose, commands, and unknowns for user confirmation.

Before writing, present:

- project root, derived project name, and exact target;
- facts with sources, AI inferences, unknowns, and conflicts;
- discovered technology-stack facts and added knowledge requests;
- files to create and validation command;
- confirmation request.

## Materialize after confirmation

1. Create a unique staging directory inside the project root; never stage over the final target.
2. Copy `assets/templates/core/doc-project/` into staging.
3. Replace exactly `{{PROJECT_ID}}`, `{{PROJECT_NAME}}`, `{{KNOWLEDGE_BASE_NAME}}`, and `{{INITIALIZED_AT}}`; fail if any `{{UPPER_CASE_MARKER}}` remains.
4. Record each confirmed technology in the shared technology-stack document; technology discovery never creates a second knowledge base or selects a stack-specific template.
6. Copy `assets/scripts/` and `assets/schemas/` to `.project-kb/scripts/` and `.project-kb/schemas/`.
7. Populate only confirmed initial knowledge. Keep unknown values `missing` or `proposed`.
8. Run validation against staging. Rename staging to the final target only when validation has zero issues and the final target still does not exist.

Do not create `AGENTS.md`, `CLAUDE.md`, or any sibling file outside the confirmed knowledge-base target. On failure, report the staging path and do not claim initialization succeeded.
