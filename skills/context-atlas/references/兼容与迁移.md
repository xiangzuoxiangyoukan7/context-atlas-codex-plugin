# 兼容与迁移

## 两种版本各管什么

- `project_version`（项目版本）跟随业务项目发布，例如 `1.4.0`。
- `format_version`（知识库格式版本）只表示文档结构和字段规则，例如从旧的裸来源编号升级为文件链接。

知识库工具升级时先读取 `compatibility.json`。可读的旧格式可以继续读取；只有文档表达逻辑变化时才做等价转换，不为了追求最新版而强制迁移。未知格式必须停止正式写入并报告，不得猜测。

## 只读诊断

在知识库根目录的父目录执行：

```text
python <知识库>/.project-kb/scripts/agent_kb_operation.py diagnose-format <知识库>
```

报告中的 `write_blocked`（是否禁止正式写入）为 `false` 才可继续知识更新。`conversion_available`（是否存在转换器）为 `true` 只表示可以提出迁移，不表示已获批准。

## 轻量转换

先运行 `migrate-propose`（生成迁移提案）：

```text
python <知识库>/.project-kb/scripts/agent_kb_operation.py migrate-propose <知识库>
```

向用户展示完整变更文件、未解析项和 `proposal_revision`（提案修订号）。只有用户明确确认同一修订号且未解析项为空，才运行 `migrate-apply`（应用迁移）：

```text
python <知识库>/.project-kb/scripts/agent_kb_operation.py migrate-apply <知识库> --proposal-revision <修订号> --confirmed-revision <同一修订号>
```

当前转换保留旧字段 `sources` 作为旧格式兼容信息，同时新增统一文件关系 `rel_supported_by` 作为当前权威关系。转换只更新 `format_version`，不得改变 `project_version`，也不得借迁移改变业务含义。
